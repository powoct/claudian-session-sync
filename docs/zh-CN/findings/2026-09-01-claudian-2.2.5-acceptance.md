## A · 判据换了一种,结论没变

附录原本的判据是「报告里存在一行 Session 列是 `<前 8 位>` 的记录」。这一轮**没截到**那一行:
点完第二次「Sync now」到打开报告之间夹了一轮自动 pass,而**报告只保留最近一次**,
看到时已是收敛后的 `NOOP`。

改用**传输证据**判定,复核成立:

```
diff sA-before sA-after → replica:
  + <ws>/grok/01a05c03-…/chat_history.jsonl    (17,886 B)
  + <ws>/grok/01a05c03-…/rewind_points.jsonl   (206 B)
  + <ws>/grok/01a05c03-…/summary.json          (1,112 B)
  + <ws>/grok/01a05c03-…/updates.jsonl         (4,370 B)
```

**0.2.0 下这里是一片空白**——记录压根不进候选集,不产生任何一行、也不写任何一个文件。
所以传输发生就等于准入发生。B 机四个文件 sha256 与 A 侧逐字一致,`grok --resume` 历史完整。
附录已把这条等价判据写进 A.4,并在 A.4 与 D1–2 各补了一句「点完立刻看报告」。

## D · 「搬」的三条证据

| 层 | 打开前 | 打开后 |
|---|---|---|
| flat | 111 | **113** |
| `devices/<A 的 key>` | 2 | **0** |
| `devices/<第三台的 key>` | 1 | 1 |

1. **设备层清空**:+2 / −2,且只动本机那个目录。**一轮就搬完**,没有出现「两层都还有」的半完成态。
2. **两台是同一份**:B 机改名 → 送回 A → **A 侧也变成新名字**。
   ADR-67 的复制方案里 A 会固执地显示原名,这条正是搬运相对复制的收益。
3. **不撤回,但也不再搬新的**:关掉开关后老那条**仍在 flat**;A 机新建的一条(Claude Code)
   **只在 `devices/<A 的 key>/`、从未出现在 flat 层**。

**D6 的代价看得见**:flat 那一行悬停时确实出现 `Assign to this device` 图标,紧挨垃圾桶。
未点击,vault 里没有生成任何 `.assigned.json`——与 OQ-25「既不写也不复制」的决定一致。

**开关存在哪里,快照也复核了**:`state/workspaces/<ws>.json` 在 D 窗口内 489 → 520 B,
即 binding 里多出的机器本地同意位;`data.json`(随 vault 走的设置)**未变**。这正是 ADR-69
要的「A 机打开不会顺带打开 B 机」——B 机全程未打开,记录里逐条确认。

**同时被证实的一条分离**:D7 那条新对话的**会话文件照样同步进了 replica**,尽管它的记录
从没进过 flat 层。准入读所有设备目录、显示与否由 Claudian 决定——ADR-65 (c) 支的否决理由,
在真机上的正面复验。

1. **步骤 A / C 用的 provider 是 grok,不是 claude-code**:Claudian 的模型选择器当时点不动。
   附录没有限定 provider,而准入走的是四个 adapter 共用的同一个 `readVaultScope`。
   **D7 的新对话是 Claude Code**,两种 provider 都覆盖到了。
2. **A 首轮/推送轮的报告行未逐字截到**(见上)。
3. **D1–2 的「moved to the shared layer」Notice 未捕捉到**——同一个报告窗口问题。
   判据是层计数,Notice 只是旁证;验收人如实记「未捕捉」而没有拿它当通过依据,是对的。

## 套件缺陷:`check` 连着三轮红在同一条上(已修)

`check sC-before sC-after` 报 `✗ I1 VIOLATED`,唯一那条是**跑验收的那个 CLI 自己的
记录文件**(162 → 184 MB,随对话不断重写)。复核确认它在**任何一张快照**的
replica / backup / state 里都不存在——插件从未搬运过它,不在 I1 的射程内。

**危险的不是这条红,是它每轮都要人用嘴解释掉**——而 C3 的剧本写着「不 ✓ 就立刻停下上报」。
第三轮之后,操作者对这条红的默认反应已经变成「又是那个」,真违规将来正是从这里溜过去。

已修(套件在 `tmp/`,不入库):`check` 现在只把**插件搬运过的**本机文件算进 I1
(判据:replica 里有同一个 session id),其余的**出声列出来**但不计入判定;
若其中有文件在窗口内变过,逐条点名。注入验证:把一条真被搬运过的版本抹成不可达,
仍然 `✗ I1 VIOLATED` + exit 1。
同轮另修一条:`diff` 不再把 `.aiss/manifest.json` 变小标成 `⚠ SHRANK`——
它是各机只重写自己处理过的条目的缓存,Windows 的 E0 签名序列化得比 macOS 短几个字节,
变小是常态,标成警告只会让人去追一个不存在的问题。
